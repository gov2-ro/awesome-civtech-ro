## 4. Existing inventories and INS

- Listing `https://ins.gov2.ro/api/datasets?limit=1`: HTTP 200, 557 bytes, `total` 3,368 datasets, 16 card members. The llms.txt file says "about 3,600". Only `limit=1` was run; `offset` is documented but unverified.
- Five metadata records were read: ACC102B (available again, same body hash as on 2026-10-24), POP107D, LOC101B, TRN139A and GOS104A. The codes come from the pages of the projects that name them, and every use has an exact locator in the registry: POP107D (`constru-pentru-cine`, `orasul-care-se-intinde`, `demoanaf`), LOC101B (`constru-pentru-cine`, `orasul-care-se-intinde`, `biografia-localitatii`), TRN139A and GOS104A (`unde-se-termina-asfaltul`; GOS104A also `biografia-localitatii`).
- Each record separates one indicator (the definition text), four to six dimensions and the dimension values, which appear only as samples of at most five codes with their labels. A dimension value is never a variable. Each dataset has one measure field `OBS_VALUE` whose declared unit comes from the unit dimension: persons (POP107D), number (LOC101B), kilometres (TRN139A, GOS104A). ACC102B declares two units (persons and per mille), so no single unit is chosen.
- Misleading example: llms.txt presents `GET /api/datasets/ACC102B?lang=en` as "GDP". The record is workplace accidents (`CATEGORY`, `REF_AREA`, `TIME_PERIOD`, `UNIT_MEASURE`). Its source note names the Labour Inspectorate (Ministry of Labour); INS distribution alone does not prove authorship, so the proposal D160 is limited to that dataset and does not change the INS relation.
- The `POP101A` example route of llms.txt was not re-measured. The 404 in the brief stays an unverified claim here.
- Coverage differs between the mirror and the projects. LOC101B time options end in 2023 against 1990–2025 in `constru-pentru-cine`; POP107D ends in 2025 against 2026; TRN139A ends in 2024 against 2025. The projects read TEMPO directly; these records are metadata from the ins.gov2.ro mirror and are labelled so.
- Locality dimension labels begin with a number (for example `38731 RIPICENI`). The POP107D note declares SIRUTA 38731 for Ripiceni and 98916 for Scânteia, and the options carry exactly those numbers, while a second Scânteia has 94429. This supports but does not prove that the leading token is SIRUTA for all localities; it stays an ambiguity note in `siruta`.
